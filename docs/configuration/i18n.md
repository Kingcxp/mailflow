# i18n

## Built-in packs

- `en` (English) — the complete baseline; every key is defined here.
- `zh-CN` (简体中文) — Simplified Chinese; key parity with `en` is enforced
  by a unit test.

The default language is `en`. Switch with `lang set <code>` in the command
shell or the Settings tab of the TUI; the choice is persisted by the storage
backend (`preferences.language`) and restored on the next start.

## External packs

Other languages load as **data-only JSON** files from configured
directories (`[i18n] extra_dirs`):

```json
{
  "locale": "ja",
  "name": "日本語",
  "messages": {
    "mail": { "list_title": "メール（{count}）" },
    "command": { "help": { "title": "MailFlow コマンド" } }
  }
}
```

- `locale` — the code users select; `name` — the display name; `messages` —
  a nested object of keys. Nested keys are flattened with dots.
- A **partial** pack is fine: any missing key falls back to English, then to
  the key itself.
- Packs are executable-code-free: no Python, only data.

See `translations/example.ja.json` for a sample (loaded from the
`translations/` directory in the example configs).

## Key conventions

- Dotted namespaces: `command.help.title`, `mail.list_title`,
  `tui.reply_prepared`, `cli.shell_prompt`, ...
- `{name}` placeholders are formatted with `str.format` parameters
  (`service.t("mail.not_found", mail_id="m1")`). Literal braces in a message
  must be escaped as `{{ }}`.
- All user-visible strings in Core commands, the CLI, the TUI and notifiers
  go through `service.t(...)` / `I18n.t(...)`.
